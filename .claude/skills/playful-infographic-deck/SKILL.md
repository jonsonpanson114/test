# 手づくり感のあるインフォグラフィック資料

営業が「これを使いたい」とお客さんに思ってもらうための資料を、**社内資料の事実だけで**、**見て楽しい形**に作る。
元になったのは、4人用ワークブース「IDO」のPR資料づくり（14ページ）。最初の版は「きれいだが型にはまった社内プレゼン」と言われ、フライヤーの付箋・話しかける口調に寄せて作り直したら「この作り方が良かった」となった。その差を再現するためのスキル。

## 先に押さえる3つの原則（なぜ効いたか）

1. **カードを均等に並べない。** 白いカードを同じ大きさで揃えると、それだけでPowerPointに見える。付箋・ポラロイド・ちぎった紙・紙タグを、少し傾けて重ねる（`--r:-2deg` 〜 `3deg`）。傾きは1枚ずつ変える。
2. **話しかける口調にする。** 「仕様の説明」ではなく「導入すると何が良くなるか」から始める。見出しは「こんな場所、足りていませんか？」「何をするかは、あなたの自由。」。補足は手書き風フォントで。資料側（フライヤー等）に既にある言い回しがあれば、そのまま借りる。
3. **画像は渡された資料のものだけ。** 製品の写真・CG・図は、切り出して使う（トリミングと拡大縮小まで）。AIに描き直させると形・色・日本語が崩れる。自作してよいのは、アイコン・図面風の線画・模式図・背景だけ。

## 進め方

### 1. 素材を読む
- 渡されたPDF・資料を**全部読む**（ページ指定で全ページ）。仕様書は数値・条件・制約の宝庫。
- 画像の抜き出し: `scripts/extract_images.sh <pdf> <outdir>`。コンタクトシート（`_sheet.jpg`）を**目で見て**、どれが何の画像かを確認してから使う（番号だけで選ばない）。
- 同じ写真でも「写真」か「CG」かを区別しておく（キャプションに書くため）。
- 元資料が【社外秘】なら、最後に必ず公開可否の確認を促す（下の確認リスト）。

### 2. 構成を決める（1枚＝1メッセージ）
標準の流れ（8〜14枚）。素材に合わせて増減してよい。
| 役割 | 内容 | 見せ方の定石 |
|---|---|---|
| 表紙 | コピー＋主要数値3つ | 付箋の壁（背景）＋ちぎった帯に見出し＋数字はスタンプ＋製品はポラロイド |
| 課題→解決 | お客さんの悩み4つ → 「〇〇なら」 | 悩み＝付箋、答え＝同色の丸いシール、間に写真 |
| コンセプト | 名前の由来・使い方の例 | 大きな見出し＋「I DO ＿＿」のような空欄＋用途の付箋の散らし |
| 機能・設備 | 何が付いているか | 写真に**手描き風の矢印とラベル**で直接書き込む |
| 仕様選択 | 選べる色・部材 | 紙タグ（穴あき）を傾けて並べる／色分けの線画 |
| 安心材料 | 性能値・法規・安全 | 濃い背景に特大の数字。法規は「シール」で |
| サイズ・条件 | 寸法・設置条件 | 方眼紙に図面風、チェックリストは罫線ノートに手書き |
| 事例・パターン集 | いろんな組み合わせ | `references/design-system.md` の「パターン集」を参照 |
| クロージング | 次の一歩 | 表紙と同じ付箋の壁で締める（ブックエンド）。問い合わせ先は空欄のまま見えるプレースホルダ |

最初に**構成案を文章で出して合意を取る**必要はない。まず作って見せ、直しを受けるほうが速い（このプロジェクトでもそうだった）。ただし、複数の方向性で迷うときは、同じ内容を別テイストで2〜3枚だけ作って見比べてもらう。

### 3. 作る
- `assets/template.html` をコピー（部品CSS＋3枚のデモスライド）。`scripts/setup_fonts.sh <dir>` でフォント（丸ゴシック／手書き風／Outfit／Noto Sans JP）を取得し、`fonts.css` を同じ場所に置く。
- スライドは `<section class="slide">`（1920×1080）。部品と配色の使い方は `references/design-system.md`。
- 製品色（`--accent`）を1色決め、付箋色（オレンジ・イエロー・ブルー・ピンク・グリーン）は全ページ共通にする。色が増えるとうるさくなる。
- ページ番号は `.pg` を置くだけで自動採番（並べ替えても直す必要がない）。

### 4. 見て直す（ここを省かない）
1. `node scripts/render.js deck.html out --scale 1` でPNG化し、**全ページを画像として見る**。コードだけ見て判断しない。
2. 直す定番: 日本語の折り返し（`white-space:nowrap`／幅／フォントサイズ）、傾けた要素どうしの重なり、写真キャプションと隣の写真の衝突、帯の文字が隠れる、はみ出し。
3. 修正→再レンダリングを、全ページ問題なくなるまで繰り返す。複数ページは `montage` で一覧にすると速い。

### 5. 書き出す
- `node scripts/render.js deck.html out --scale 2 --pdf deck.pdf`（PNGは3840×2160、PDFはベクターで1ページ1スライド）。
- 複数のHTMLから1冊にまとめるとき: `scripts/merge_pdfs.sh out.pdf a.pdf:1-5 b.pdf:all a.pdf:6-8`。
- 成果物は、PDF・PNG・全ページ一覧画像・元のHTMLと素材（文言修正の再出力用）の4点を、同じフォルダにまとめて渡す。

### 6. 渡すときに必ず伝える
`references/content-rules.md` の確認リストのうち、その資料に当てはまるものを、**質問の形ではなく「確認してほしいこと」として箇条書きで**。特に: 社外秘の扱い、こちらで付けた名前・提案、自分で計算した数値、法規まわりの言い回し、空欄の問い合わせ先。

## 内容を守るルール（要点。詳細は references/content-rules.md）
- 数値・仕様は資料のまま。**測定値は条件（周波数・測定環境・参考値である旨）とセット**で書く。
- 「完全防音」「〜は不要」など**断定表現は使わない**。法規は「〜に配慮した仕様」「要申請」「物件ごとに確認」。
- 資料に無いことを事実として書かない。自分で付けた名前・用途の提案・換算値は、**資料に無い案**として最後に報告する。
- お客様向けの文面に「社内資料」「勉強会資料」などの言葉を残さない。
- 連絡先・担当者名は作らない。`［部署名・担当者名］` のように見える空欄にする。

## 使い方の例
- 「この仕様書とフライヤーからPR資料を作って」→ 1〜6を通しで。まず8枚前後。
- 「もっと面白みを」→ 原則1・2に戻って、均等配置になっている箇所を探して崩す。
- 「事例をもっと見せたい」→ `references/design-system.md` の「パターン集」。選べる仕様の制約を先に表にしてから、その範囲で組み合わせる。
- 「別のテイストも見たい」→ 同じ内容で、雑誌風／ポップ／ダーク／青焼き図面風／ベント（タイル）の方向を2〜3枚ずつ。ただし、**まず聞くべきは「別テイスト」なのか「同じテイストで中身を増やす」のか**（このプロジェクトでは後者だった）。
